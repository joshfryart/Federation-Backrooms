# Sign art, batch 10 (`js/signart.js`)

Viewer: `viewer-signs.html` (serve the repo root). `?set=3d&view=wall|floor|pod|dir` (wall decals, floor zones, pod hatches, directory; `?cam=x,y,z,tx,ty,tz`, `?spin=0`, `?static=1`) and `?set=icons` (HTML sheet: U-1 glyphs, U-2 badges, G-1 emblems, U-3 deck-plan symbols).

Covers asset-gaps.md section 11.4 G-1, G-2, G-3, G-4, 11.5 R-1, 11.7 U-1, U-2, U-3 (batch 10). Everything is original: no crosses, deltas, wings-and-star marks or other borrowed insignia. Pure three.js plus `js/icons.js` (pure data, imported, never edited). Canvas textures need a DOM; tables, DECOR kits, icon paths and symbol recipes are plain data.

## Integration (nothing here edits an existing file; exact hook-ups)
1. **Icons** (no edit of `js/icons.js`): once at start-up (before the HUD builds its sprite), `import { installIcons, HH_MAP } from './signart.js'; installIcons();` merges the new paths into the live `ICONS`, `SHAPES` and `CATS` objects, so `iconSvg('regen')`, `badgeSvg('person', 'flight')` and `spriteSvg()` work. `js/menus.js` `HH_ICON`: `Object.assign(HH_ICON, HH_MAP);` after its literal (replaces dermal -> hypo, scalpel -> lab, plasma_torch -> fire, extinguisher -> fire, mop -> clean, cargo_hook -> grab, crowbar -> workshop, phaser_rifle -> phaser). U-2: wherever a department picks a badge category (nav HUD, minimap `drawBadge`, contact cards), map department `flight` to category `flight` and `operations` to `operations` instead of the shared ones; `CATS` then has nine entries.
2. **Emblem plates** on room doors / lockers, `js/world.js` sign pass (`_details`, next to `place(...)`): `import { buildEmblemPlate, ROOM_DEPT } from './signart.js';` and after the room-name sign for each room `r`, on the same wall face `f`: `const p = buildEmblemPlate(ROOM_DEPT[r.type] || 'services'); p.position.set(f.px + f.dx * 0.02 + side * 0.85 * (-f.dy), 1.6, f.pz + f.dy * 0.02 + side * 0.85 * f.dx); p.rotation.y = f.ry; g.add(p);` (`side = 1` puts it beside the sign; `1.6` is eye height; the plate is 0.31 m wide). One shared texture per department, so 8 textures per game.
3. **Placards**, same pass: `import { buildPlacard, PLACARD_ROOMS } from './signart.js';` for each wall face `f` of a room whose type is in `PLACARD_ROOMS` and with `rnd() < 0.3`: `const m = buildPlacard(PLACARD_ROOMS[f.room][Math.floor(rnd() * PLACARD_ROOMS[f.room].length)]); m.position.set(f.px + f.dx * 0.012, 1.45, f.pz + f.dy * 0.012); m.rotation.y = f.ry; g.add(m); f.deco = true;` (mark the face so the decor pass skips it, or leave it free: a placard is 0.25 m).
4. **Floor zones**, `_details`: `import { buildFloorZone, ZONE_ROOMS } from './signart.js';` for rooms of the listed types, on 1 to 3 random interior tiles that hold no prop: `const z = buildFloorZone(kind); z.position.x = (tx + 0.5) * TS; z.position.z = (ty + 0.5) * TS; z.rotation.z = quarterTurn * Math.PI / 2; g.add(z);` (the mesh is a floor plane: spin it about its own Z in this orientation, `rotation.order = 'YXZ'` if you set `rotation.y`). Use `podarrow` on the airlock tiles that lead to the hatches (point them along the wall). For many tiles of one kind use an `InstancedMesh` over `z.geometry` and `z.material`.
5. **Directory** in lift lobbies (`js/world.js`, where `this.lift` is set): `import { buildDirectory } from './signart.js';` then `const b = buildDirectory(d.rooms, { deck: d.deck + 1, here: { x: liftTileX, y: liftTileY }, accent: '#' + new THREE.Color(ship.accent).getHexString() }); b.position.set(wx, 1.5, wz); b.rotation.y = faceRy; g.add(b); this.directory = b;` and in the per-frame update `this.directory?.userData.pulse(t)`. The board needs a free wall face next to the lift (use the first of `wallFaces` within 2 tiles of `liftPos` that is not `sign`ed); it also answers `TODO.md:20` ("corridor has no location sign").
6. **Pod hatches** (R-1): `import { DECOR_SIGN, DECOR_SIGN_POOLS } from './signart.js'; Object.assign(DECOR, DECOR_SIGN);` after `Object.assign(DECOR, DECOR_ENG);`, and `ROOM_DECOR.airlock.push('podbank')` (single `podhatch` for 1-tile faces). Per `docs/asset-gaps.md` R-1 the escape pod bay has no room type, so the hatches only appear in airlock (EVA prep) rooms for now; the floor arrows are `buildFloorZone('podarrow')` on the tiles in front of them. `abandon_ship` sends crew to `airlock/door` already, so the hatches give them somewhere believable to walk to.
7. **Deck-plan symbols** (U-3), `tools/artifact/deck-plans.template.html` prop drawing `switch` (line ~222): the page is a single built HTML file, so copy `PROP_SYMBOLS` and `drawPropSymbol` into it (or let `build-deck-plans.sh` bundle `js/signart.js` with esbuild) and change the default branch to `default: if (!drawPropSymbol(g, p.kind, s, { panel: C.panel, ink: C.ink, sci: css('--sci') })) rr(s * 0.45, s * 0.45, 2);` (the context is already `g.translate(cx, cy)`, `s = px * 0.62`). Add `Object.assign(PROP_NAME, PROP_NAME_X)` for the tooltips.

## Limits and notes
* The pod bay itself (inventory space 59) has no room type, so R-1 is a wall fixture for the airlock room, not a room.
* Room names on the directory use no text of their own (department legend only); add per-room labels in `drawDirectory` if the board should read like a map key.
* The emblems are drawn from the existing `SHAPES` outlines, so plates and badges agree; the Security plate uses the triangle (`tri`) shape and the Medical plate the circle.
* U-1 glyphs are first-pass line art at 24 px; check them at 16 px in the wheel and duty board before shipping.
